# Symfony experiments for UXor

Reviewed November 18, 2026 against the demo on Symfony 8.1.11 and UXor’s development setup on Symfony AI Mate 0.14.0.

## Asset delivery and diagnostics

- **AssetMapper 8.2.0-BETA2** offers `framework.asset_mapper.importmap_entries: reachable`. It follows literal dynamic imports as well as static imports. The Stimulus controller registry can therefore keep a lazy controller in the inline map even on pages where the browser never fetches it. A trial on the dashboard should compare compressed HTML size and actual module requests separately. [Symfony release status](https://symfony.com/releases/8.2) · [AssetMapper changes](https://symfony.com/blog/new-in-symfony-8-2-assetmapper-improvements)
- **UX Inspector** is an experimental development tool that shows Stimulus connections and Turbo fetch and render events. It can help answer whether Turbo handled a specific navigation, including when the visible page text looks the same after a full reload. The dashboard already runs Turbo 8 with hover prefetch for eligible links. [Inspector documentation](https://symfony.com/bundles/ux-inspector/current/index.html) · [Turbo Drive](https://turbo.hotwired.dev/handbook/drive#prefetching-links-on-hover)
- **UX CSS and DesignTokens** are relevant to a shared motion API. UX CSS has a published 3.7.0 experimental package. Its variant helper `cva()` appears in the development changelog for 3.8. The DesignTokens proposal is still open and the proposed CSS integration closed unmerged. The existing CSS custom properties give UXor a concrete reference when evaluating these APIs. [CSS release](https://github.com/symfony/ux-css/releases/tag/v3.7.0) · [CSS changelog](https://github.com/symfony/ux/blob/3.x/src/Css/CHANGELOG.md) · [DesignTokens proposal](https://github.com/symfony/ux/pull/3932) · [Integration proposal](https://github.com/symfony/ux/pull/4181)

## Symfony AI and the dashboard

**Mate 1.0.0-BETA1** is relevant to UXor’s recipe discovery and development tools. An isolated Composer dry-run on PHP 8.5.12, with the root lockfile and plugins and scripts disabled, resolved exactly three updates when Mate, the Symfony Mate extension and the Mate Composer plugin were each pinned to the beta. Pinning just the first two failed under the project’s stable dependency policy. The check established dependency resolution only. A runtime trial would verify discovery of UXor’s seven tools and three skills before changing its supported versions. Symfony’s compatibility promise begins at 1.0 final. [Beta announcement](https://symfony.com/blog/symfony-ai-1-0-0-beta1-ai-and-mcp-hackathon) · [Mate documentation](https://symfony.com/doc/current/ai/components/mate.html)

**AG-UI and Turbo** are the closest fit for an interactive dashboard experiment. SymfonyCon Warsaw has a November 26 demonstration scheduled for agent-operated charts, maps and autocomplete using a PHP AG-UI implementation. The Symfony AI beta contains no identifiable packaged AG-UI adapter. A small UXor experiment could let a user ask to see weekly revenue, validate the period against the dashboard’s existing choices, and display the same chart and accessible data table through Turbo. It would exercise the UI contract without adding an AI dependency to the initial page load. [Session description](https://live.symfony.com/2026-warsaw-con/schedule/symfony-ux-symfony-ai-taking-agent-interactions-to-the-next-level) · [Tagged Symfony AI source](https://github.com/symfony/ai/tree/v1.0.0-BETA1/src)
