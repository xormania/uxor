# UXor audit working notes: demo, PHP tests and test guarantees

## Assessment

The existing demo is a deliberately trusted, development-only integration fixture. Preserve that boundary when importing package development tools; it must not become a package service, bundled consumer app, or public dynamic deployment by accident. The static gallery is a different publication surface. PHPUnit, real Live requests, offline-provider firewall journeys, hostile browser-parsed markup and deterministic Turbo transition tests together offer substantial existing protection. This audit found no basis to replace that test architecture wholesale.

170 PHP test methods are declared in the tracked demo test tree (data-provider cases are additional); no tracked `markTestSkipped`, `markTestIncomplete`, skipped/incomplete attributes, or no-assertion exemptions were found. The method count is a source inventory, not an executed test count. The baseline contains 354 tracked `demo/` files: 51 source files, 123 templates, 35 test/support/snapshot files, 72 SVG icons, 14 raster/animated image resources, and 59 configuration/support files. The product security review also covers `demo/tests/OAuth`, `Editor`, and `MarkdownEditor`.

### UXOR-AUD-TEST-002 — P2: fuzzing silently accepts its own settle timeout

**Current fact.** The UI fuzzer says it waits until no request or busy frame remains ([release.fuzz line 375](https://github.com/xormania/uxor/blob/40d957cd1ea7766ac0dee742816948ce5ae05bc3/tests/e2e/release.fuzz.spec.ts#L375)). It stops polling in-flight requests after 200 × 50 ms with no assertion, catches the busy-state timeout, and catches the animation-frame evaluation failure ([lines 376 onward](https://github.com/xormania/uxor/blob/40d957cd1ea7766ac0dee742816948ce5ae05bc3/tests/e2e/release.fuzz.spec.ts#L376)). The loop then asserts errors and duplicate controllers; the final completeness assertion checks connected controllers, not pending requests or busy flags ([line 431](https://github.com/xormania/uxor/blob/40d957cd1ea7766ac0dee742816948ce5ae05bc3/tests/e2e/release.fuzz.spec.ts#L431)). A frame permanently left busy can therefore satisfy the remaining assertions.

**Executed evidence.** `node /workspace/scratch/uxor-audit-2026-10-16/e2e-fuzz-settle-repro.mjs` extracts and executes the original helper against a mocked Playwright page whose busy wait rejects. It exits 0 and reports `settle resolved despite busy-check timeout`. This is an isolated JavaScript control-flow reproduction, not an actual browser or product deadlock reproduction.

**Affected consumers.** Release UI fuzzing, especially navigation/async regressions whose visible result is a stuck loading state rather than a logged exception.

**Concrete work.** Enforce a bounded settle deadline and fail with pending request URLs, frame IDs/busy attributes, the seed and recent actions. Keep expected non-actionable random-click misses distinguishable from a page that never settled. Catch an evaluation failure only when a known navigation replaces the document, then wait for the replacement's readiness.

**Dependencies and preservation risk.** No product-code or package dependency change is required. Keep the existing seed/action diagnostics and expected canceled-navigation handling. ## Sound areas and boundaries to preserve

- Keep the shared fixture, deterministic transition recorder, actual native-dialog top-layer assertions and value-policy matrix. They establish different guarantees and avoid many weaker duplicated journeys. The inventory's R1–R8 reductions generally preserve distinct visual, integration and repeated-lifecycle boundaries; do not remove screenshot tests solely because they repeat an action.
- CI forbids exclusive tests, retries once, never silently updates screenshots and retains failed traces ([playwright.config.ts:150–167](https://github.com/xormania/uxor/blob/40d957cd1ea7766ac0dee742816948ce5ae05bc3/playwright.config.ts#L150-L167)). Retried success remains a pass but is called flaky in result summaries; CI-report parser/attempt handling is audited by the CI/tool owners. No active `test.fail` or `test.fixme` marks were found in tracked E2E or recipe specs. Intentional skips are release specs restricted to Chromium and a matrix-definition completeness check restricted to one browser project.
- Keep the PNG baselines as reviewed artifacts. All 352 recipe PNGs and the placeholder passed integrity checks. This establishes readable artifacts, not that pixels match current application rendering.
- The layout and OAuth demo tests exercise real Symfony behavior at the application boundary, while provider HTTP is separately mocked. They do not prove live third-party provider application configuration. Do not replace the independent fresh consumer with a demo-only test when importing package tooling.
- Counters are not leak proofs: the listener tracker explicitly excludes detached targets and one-shot listeners; release long-session tests supply a different GC-based boundary. JS coverage records Chromium pages used by fixtures and recipes' controller scripts only; extra manually created pages and shared non-controller modules are not measured. Those are explicit scope limits, not 0% product coverage claims.
- Release timing thresholds are deliberately absent pending owner tolerance decisions; do not relabel green timing reports as budget enforcement.
