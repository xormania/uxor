## UXOR-AUD-PKG-004: Same-repository reference generation requires a noncircular freshness and provenance contract

**Classification:** required migration/design blocker; P1 high; confirmed source; high confidence. **Evidence:** [clean HEAD and tracked file requirements](https://github.com/xormania/uxorscient/blob/614aa28fd937baa9feffa7730d02b58dc73afe18/tools/ReferenceGenerator.php#L27), [embedded revision](https://github.com/xormania/uxorscient/blob/614aa28fd937baa9feffa7730d02b58dc73afe18/tools/ReferenceGenerator.php#L105), [index revision/URLs](https://github.com/xormania/uxorscient/blob/614aa28fd937baa9feffa7730d02b58dc73afe18/tools/ReferenceGenerator.php#L119), [output path/check behavior](https://github.com/xormania/uxorscient/blob/614aa28fd937baa9feffa7730d02b58dc73afe18/tools/generate-reference.php#L17).

Current generation correctly treats UXor as a separate clean upstream snapshot. It requires `--revision == source HEAD`, forbids any dirty/untracked file, embeds that revision in index and rewritten links, and writes package resources in a second repository. In one repository, editing canonical docs makes the source dirty; generating output then committing it changes the containing commit SHA. Requiring the generated bundle to embed its own containing commit SHA is self-referential and cannot be fixed solely by excluding generated files from the dirty check.

**Recommendation:** specify canonical input set and stable content identity (input digests/tree), source-link provenance policy, generator/package roots and normal working-tree editing semantics. Options include content-based freshness plus a separately identified prior source revision whose relevant canonical bytes are verified unchanged, or a documented stable revision/link representation without claiming candidate-self identity. Choose a practical provenance contract before implementation, retaining honest immutable source attribution when available. CI regenerates into a temporary view, compares committed outputs, and fails without silently repairing them. Generated output is never its own authoritative input.

**Acceptance:** edit a canonical recipe/document, regenerate before committing, commit once, and check the resulting commit without a new rewrite; unrelated changes do not churn bundle provenance; stale changed input fails; links/hashes meaningful; files are already committed when tagged. Preserve existing strict cross-repository snapshot mode if useful, with tests for the distinct same-repository mode. No package/Toolkit dependency upgrade needed.
