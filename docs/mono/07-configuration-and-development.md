# Configuration ownership, documentation and local helper audit

Baseline: `xormania/uxor@40d957cd1ea7766ac0dee742816948ce5ae05bc3`. Direction inputs: the supplied single-repository proposal and configuration concept. This is a read-only source audit and a proposed ownership map; no package subtree, configuration framework, workflow generation, registry integration or publication has been implemented by this review.

The existing native owners are a good starting point. Keep Toolkit manifests, the future root Composer manifest, application Composer roots and locks, the Playwright image pin, the curated recipe catalog and native application configuration. A single global version or ignore list would conflate independent contracts. The smallest justified additions are a concise repository/audience map, a common check entry point where commands really overlap, and—only for repeated executable defaults—a small typed development profile with committed native representations where necessary. Exact filenames for a new profile or role map remain an implementation choice; a new general-purpose configuration framework is not required.

## Findings and register links

### UXOR-AUD-CFG-001 — Installed commit hook excludes text that Git can retain

Category: existing local policy guarantee defect; confirmed by an actual local Git commit. Priority P2, effort S/M, low-to-medium risk from verbose-editor false positives. This does not demonstrate a bypass of the independent CI metadata check.

At [hook lines 7–9](https://github.com/xormania/uxor/blob/40d957cd1ea7766ac0dee742816948ce5ae05bc3/tools/hooks/commit-msg#L7-L9), the hook claims Git always removes everything following a scissors line. [Line 18](https://github.com/xormania/uxor/blob/40d957cd1ea7766ac0dee742816948ce5ae05bc3/tools/hooks/commit-msg#L18) unconditionally splits there before looking for forbidden account references. The [test at lines 63–72](https://github.com/xormania/uxor/blob/40d957cd1ea7766ac0dee742816948ce5ae05bc3/tools/tests/check-github-mentions.test.mjs#L63-L72) mirrors that assumption and invokes the hook directly, rather than inspecting the final commit.

An isolated scratch Git repository installed the actual hook and ran `git commit --allow-empty -m` with an ordinary subject, a literal scissors marker and then a forbidden mention-shaped token. The commit returned 0; `git log -1 --format=%B` retained the marker and token. Evidence: `mention-scissors-repro.json`. No remote was written. The full-message Node scanner remains independent, and `metadata.yml:54–55` checks complete persisted messages after push; the defect is the local prevention guarantee.

Required outcome: check every token that will survive in the stored message. Conservatively scanning the complete supplied message is acceptable; if editor/verbose cleanup exceptions remain, establish the cleanup behavior rather than assuming a literal marker proves removal. Preserve the self-contained installed hook: it must not start executing mutable tracked code when another branch is checked out. Update the tracked hook, real-Git tests and contributor refresh instructions together; existing installed hook copies will not update themselves.

Acceptance: actual scratch Git commits with `-m`, `-F`, an editor, verbose mode and relevant explicit cleanup modes, followed by checking the persisted message; retained forbidden tokens must reject and intended discarded diff metadata must not create unexplained failures. Retain scanner boundary/allowlist/team/case tests and complete-message CI scanning. Location: `tools/hooks/commit-msg`, `tools/tests/check-github-mentions.test.mjs`, `CONTRIBUTING.md` setup/hook instructions. No check-name or settings change is needed. The supporting helper assertion review follows below.

### UXOR-AUD-CFG-002 — Make the combined repository's audiences and source relationships explicit

Category: migration requirement and configuration maintainability improvement, not a current missing-package exploit. Priority necessary before migration completion; effort M because paths, discovery, local setup, generated references and CI selection need combined-tree evidence; risk medium if overly broad exclusions hide new code or narrow CSS inputs without proving actual behavior.

Observed current contract: root [README.md:3–8](https://github.com/xormania/uxor/blob/40d957cd1ea7766ac0dee742816948ce5ae05bc3/README.md#L3-L8), [INSTALL.md:1–16](https://github.com/xormania/uxor/blob/40d957cd1ea7766ac0dee742816948ce5ae05bc3/INSTALL.md#L1-L16) and [FOR-AGENTS.md:3–13](https://github.com/xormania/uxor/blob/40d957cd1ea7766ac0dee742816948ce5ae05bc3/FOR-AGENTS.md#L3-L13) describe a Toolkit kit; [CONTRIBUTING.md:7–43](https://github.com/xormania/uxor/blob/40d957cd1ea7766ac0dee742816948ce5ae05bc3/CONTRIBUTING.md#L7-L43) maps a kit/demo/test repository and `:45–87` has Docker/native demo setup. There is no Composer package subtree at this baseline. [tools/kit-identity.mjs:1–38](https://github.com/xormania/uxor/blob/40d957cd1ea7766ac0dee742816948ce5ae05bc3/tools/kit-identity.mjs#L1-L38) already derives kit identity correctly from root `manifest.json`. Manifest-driven [tools/llms-txt.mjs:43–46](https://github.com/xormania/uxor/blob/40d957cd1ea7766ac0dee742816948ce5ae05bc3/tools/llms-txt.mjs#L43-L46), `recipe-imports.mjs:63–96`, `readme-versions.mjs:57–62`, `readme-pairing.mjs:138–140`, `js-duplication.mjs:175–201`, `prepare-tests.mjs:34–53` and PHP [tools/sync-demo:34–40](https://github.com/xormania/uxor/blob/40d957cd1ea7766ac0dee742816948ce5ae05bc3/tools/sync-demo#L34-L40) already identify only root child manifests; they do not need a fake manifest on `packages/`.

The selected package import needs a clear operating map: Composer/tooling checks run from the repository root; UI demo Composer/console commands run in `demo/`; independent consumer commands run in its moved fixture; recipe definitions remain root children; generated package references come from this checkout; packaged instructions serve agents in a consuming application. Root `AGENTS.md` and maintainer docs should identify source owners, generation commands and affected checks. Consumer guidance must preserve consumer-owned instructions and UI files, and must not accidentally teach this repository's GitHub account policy or development Docker layout as a consumer application requirement.

Two source-boundary relationships need explicit implementation evidence:

1. [demo/assets/styles/app.css:13](https://github.com/xormania/uxor/blob/40d957cd1ea7766ac0dee742816948ce5ae05bc3/demo/assets/styles/app.css#L13) scans the whole repository (`@source "../../.."`); [tools/prepare-tests.mjs:83–92](https://github.com/xormania/uxor/blob/40d957cd1ea7766ac0dee742816948ce5ae05bc3/tools/prepare-tests.mjs#L83-L92) deliberately hashes every Git-nonignored file for CSS freshness. Package resources and fixture documentation can therefore become indirect Tailwind inputs. Directory placement alone does not prove a package-only change cannot affect the demo. Either retain conservative browser selection, or narrow actual Tailwind sources and their fingerprint together and prove equivalent UI output/coverage before claiming package-only independence. A digest-only exclusion would falsely mark stale CSS fresh.
2. [tools/docs-lint.mjs:87–96](https://github.com/xormania/uxor/blob/40d957cd1ea7766ac0dee742816948ce5ae05bc3/tools/docs-lint.mjs#L87-L96) and [tools/icon-lint.mjs:240–259](https://github.com/xormania/uxor/blob/40d957cd1ea7766ac0dee742816948ce5ae05bc3/tools/icon-lint.mjs#L240-L259) walk Markdown recursively except specific directory names. New package instructions, references and fixtures will enter those scans. Keep positive active instructions under relevant policy, preserve explicit negative/history examples, and give fixture/reference material an intentional role rather than blanket-excluding `packages/`. [tools/name-check.mjs:111–115](https://github.com/xormania/uxor/blob/40d957cd1ea7766ac0dee742816948ce5ae05bc3/tools/name-check.mjs#L111-L115) treats only released root changelog prose as history; blindly adding the former companion slug to its former-kit list would reject required pinned migration/provenance citations. Reuse **UXOR-AUD-PKG-004** for that identity/provenance adaptation.

Required change: update root map and audience-specific guidance atomically with the imported paths; have tools read native manifests/Composer declarations for facts those formats already own. Add one small shared path/relationship declaration only where independently maintained consumers cannot derive the role from existing metadata. Keep distinct meanings for distributable payload, Toolkit lint view, runtime sources, generated output, test fixtures and historical material; do not create a universal exclusion list.

Acceptance: from a clean combined checkout, an agent can find each command's working directory and a shared value's owner; native/Docker UI setup and the independent package consumer use the same maintained checks as CI. A combined-tree fixture includes `packages/uxor/`, generated references, renamed/deleted/unknown root directories, root Composer metadata and an application fixture; verify recipe discovery still yields 64 real recipes, unknown missing-manifest content is not silently dropped, both complete-archive installation routes work and source/reference staleness fails. Demonstrate the exact checks and CSS behavior selected by package-only, recipe-only and shared-input changes. Root-owned package path/archive work is **UXOR-AUD-PKG-001**; executable sink/output/credential expansion is **UXOR-AUD-CI-004**; Mate command behavior is **UXOR-AUD-TEST-004**. This finding supplies the navigation/ownership contract rather than duplicating those implementations.

Other cross-register documentation deltas: retain the product review's stale Alert Flowbite-JS requirement and unresolved schema cleanup separately; use **UXOR-AUD-CI-006** for replacing [CONTRIBUTING.md:593–600](https://github.com/xormania/uxor/blob/40d957cd1ea7766ac0dee742816948ce5ae05bc3/CONTRIBUTING.md#L593-L600) routine published-tag deletion/movement advice with immutable-release recovery. A source guard rejecting a mismatched tag is useful; package consumers make rewriting a consumed tag a distinct owner decision.

## Confirmed finding UXOR-AUD-CFG-001 — Commit-message hook ignores text Git actually retains

- **Category/confidence:** existing local policy guarantee defect; high, reproduced with actual Git and the current copied hook in a scratch repository.

## Configuration/ownership recommendations from these tests

1. **Retain native recipe discovery.** The tests intentionally define a recipe as a root child containing `manifest.json`; a package under `packages/uxor/` should remain a non-recipe. Add a combined-tree fixture rather than making every helper understand Composer internals. Recipe import, pairing and duplication scope are separate from package PHP/resource checks.
2. **Give historical provenance an explicit rule.** [tools/name-check.mjs:111-115](https://github.com/xormania/uxor/blob/40d957cd1ea7766ac0dee742816948ce5ae05bc3/tools/name-check.mjs#L111-L115) only permits history in released root changelog text. The selected direction explicitly permits former naming in migration/history and demands pinned import provenance. Extend policy narrowly (identified historical section/file roles or a specific reference mechanism) and add cases proving stale active install/guide URLs still fail. A blanket exclusion of `packages/` or `docs/mono/` would drop active-reference coverage and is not justified.
3. **Keep scanner/hook implementations intentionally separate.** Their identical regex is a trust-boundary copy, not arbitrary duplication. One source cannot be imported at hook runtime without giving a newly checked-out branch executable control. Test outcomes against independent persisted Git behavior; update tracked hook and installed-copy instructions atomically.
4. **Align broad scans with actual inputs.** [tools/prepare-tests.mjs:82-92](https://github.com/xormania/uxor/blob/40d957cd1ea7766ac0dee742816948ce5ae05bc3/tools/prepare-tests.mjs#L82-L92) hashes all unignored Git files because Tailwind currently scans broadly; [tools/icon-lint.mjs:240-259](https://github.com/xormania/uxor/blob/40d957cd1ea7766ac0dee742816948ce5ae05bc3/tools/icon-lint.mjs#L240-L259) recursively scans all Markdown outside selected directory names. Introducing package instructions, generated references and consumer fixtures changes those inputs. Keep source-role boundaries and ignore rules consistent and exercise propagation from a package-only change; do not claim package-only local setup avoids browser/CSS work until demonstrated.
5. **Preserve meaningful atomicity tests.** `prepare-tests` validates racing processes and live/dead locks, `readme-pairing` uses real Git ranges, `recipe-imports` uses real recipe loading, and `js-duplication` injects a known violation. These give stronger evidence than a schema/config file checked against its own generated output. Do not discard them during command-entrypoint consolidation.
