# OAuth provider button

A provider sign-in link that starts the application's OAuth flow with a full browser navigation.

```twig {"preview":true}
<div class="w-full max-w-45 space-y-3">
    <twig:OAuthProviderButton provider="google" href="#" />
    <twig:OAuthProviderButton provider="facebook" href="#" />
    <twig:OAuthProviderButton provider="github" href="#" />
</div>
```

## Usage

Give `href` the application's OAuth start route, generated by Symfony's `path()` function. The server creates the authentication request and redirects to the provider. Credentials, token exchange and local-user resolution belong to the installed OAuth integration; they never appear in this component or a browser SDK.

```twig
<twig:OAuthProviderButton provider="github" href="{{ path('uxor_oauth_start', {provider: 'github'}) }}" />
```

The component chooses an outline button with a readable provider name and a keyboard focus outline. Google uses the pre-approved button images described below. It always renders an anchor with `target="_self"`, `data-turbo="false"` and `data-turbo-prefetch="false"`. Those navigation attributes, including differently cased names, are removed from the caller's attribute bag before the component supplies its own. A provider handoff starts a full browser navigation even inside a Turbo Frame, and hovering never starts the authentication flow. Turbo becomes available again on the page returned by the application.

`href` accepts a relative or HTTP(S) URL; other schemes render `#`. Supply a same-origin server route from trusted controller data. An external provider authorization URL skips the application's state handling and is not a substitute for the start route.

The built-in names are Google, Facebook and GitHub. Facebook and GitHub use text labels styled through the theme's roles. There is no provider JavaScript SDK.

Google renders the unmodified, pre-approved light and dark PNG buttons from the [Google Identity branding assets](https://developers.google.com/identity/branding-guidelines). They include the current gradient G, font, colors, padding and the text `Sign in with Google`. Both are local AssetMapper assets; light and dark visibility follows the page's theme, with no remote font, image or script request. The label is fixed to match that visible artwork, so `label` and `providerLabel` do not replace Google's text. The default example and the `social-login` block keep every provider button in a column of 180 pixels so Google has equal visual prominence. Do not stretch or recolor its images.

The copied assets are `assets/images/uxor-oauth-google-light.png` and `assets/images/uxor-oauth-google-dark.png`. Their provenance is the Android and Web, one-times resolution, rectangular light and dark buttons in [Google's official asset archive](https://developers.google.com/static/identity/images/signin-assets.zip), retrieved on 2026-10-13. These brand assets remain subject to Google's branding requirements; their inclusion does not grant a separate trademark license.

## Custom labels

For providers other than Google, `label` replaces the full button text. For another configured provider, give `providerLabel` its display name; the provider key is still passed to the application's route. Displaying a new provider does not configure its backend client. Localizing the pre-approved Google artwork requires the corresponding approved artwork and a matching accessible label in the installed template.

```twig
<div class="w-full max-w-sm space-y-3">
    <twig:OAuthProviderButton provider="github" href="#" label="Sign in with GitHub" />
    <twig:OAuthProviderButton provider="custom" providerLabel="your organization" href="#" />
</div>
```

The preview links are placeholders. The application's OAuth demo must exercise its real start route, callback and Symfony session against a mock of the external provider.
